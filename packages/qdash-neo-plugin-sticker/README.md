# @cmnyhh/qdash-neo-plugin-sticker

表情包库。**由模型自己判断存哪张** —— 它看到图、也看到上下文，比任何启发式都清楚"这张以后用不用得上"。

插件只负责三件事：存得下、找得到、发得出去。

## 安装

```bash
dsh plugin --profile web add @cmnyhh/qdash-neo-plugin-sticker
```

重启宿主。需要主包 `>=0.1.10`（用到 `instructions` 能力面）。

## 两步授权

装上之后**不能立刻用**，要去控制台「工具」页做两件事：

**① 授予工具** —— `qdash_neo_sticker` 点「授予」

不授予的话 `sticker_save` / `qq_send_sticker` 不出现在模型可见的工具里。

**② 允许引导** —— 「插件引导」那栏点「允许」

```js
const dispose = neo.instructions.register({
  key: 'sticker',
  text: '看到群友发的图或表情包，如果以后还可能用得上…' +
        '聊天里想用表情包的时候…调 qq_send_sticker 按标签找一张发出去。',
})
```

**这段是整个插件能不能用起来的关键。** 不写引导的话，模型根本想不起来存 ——
和 `memory_add` 一样：工具在那儿，但它没有"看到 X 就该做 Y"的条件反射。

引导**默认不注入**：这段文字会进系统提示，等于能改写模型的行为准则，
所以授权名单独立于工具授权（`tools.grantedInstructions`）。

## 标签怎么写

**这是检索质量的决定因素**，提示词里已经强调了：

| 写什么 | 例子 |
|---|---|
| ✅ 这张图**表达什么** | 笑死、无语、嘲讽、雀跃、不想干活 |
| ❌ 画面里**有什么** | 猫、黑白、卡通、文字 |

因为以后是**按"想表达什么"来找图**的，不是按"画了什么"。

## 目录

```
<DSH_HOME>/qdash-plugins/stickers/
  index.json          索引（标签、场合、用频）
  <hash>.png          图片本体
```

`index.json` 可以直接打开看。手工删了图片文件也不会坏 —— 索引会自愈
（`read()` 返回 null，调用方降级成"改说文字"）。

## 淘汰

上限 300 张（可配 `maxFiles`），超了删**最久没被发出去**的。

排序键是 `usedAt || at`：从没用过的按入库时间算 ——
这样"存进来就没动过"的先清掉，而不是把刚存的新图删了。

## 工具

| 工具 | 说明 |
|---|---|
| `sticker_save({ file, tags, note? })` | 存一张图。`file` 是消息里的 `[图片:xxx]` 那个 xxx |
| `qq_send_sticker({ query })` | 按标签找一张发出去。找不到返回 `{ ok: false, reason: 'no-match' }` |

**没有 `sticker_search`**：模型不需要看候选列表再选一次。它想表达"笑死"，
就该一条命令发出去；找不到就改说文字。

## 已知限制

**只能存"当场看到的图"**。

`message/inbound` 能看到所有入群消息，但模型只在被唤起时（批处理那一轮）
才看得到那一批。群里一天 200 张图、模型被叫 20 次，它大约只见得到 20 张。

这既是筛选也是遗憾：只有"聊天当下的图"会被考虑，好处是不会囤积噪音。

要"回头扫历史图"得加定时任务 —— 但那时上下文已经没了，标签质量会差很多。

**图片地址有时效**。腾讯的 CDN 链接几小时后失效，所以必须收到就下载，
不能存 URL 等以后再取。插件在内存里记最近 200 条的地址，就是这个原因。

## 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉后不注册任何工具 |
| `maxFiles` | `300` | 库里最多存多少张 |
| `maxSendBytes` | `2097152` | 单张上限（2MB）。表情包远小于这个 |
