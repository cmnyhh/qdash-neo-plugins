# @cmnyhh/qdash-neo-plugin-bili

定时把模型叫醒，让它去逛 B 站。看到值得聊的，就发一张卡片 + 一句它自己的评价。

**判断交给模型，节奏交给插件** —— 定时是机制（模型不会到点自己醒来），
挑哪条、说什么话是判断（写成规则就不是“它觉得有意思”了）。

## 安装

```bash
dsh plugin --profile web add @cmnyhh/qdash-neo-plugin-bili
```

重启宿主。需要主包 `>=0.1.10`（用到 `card` 能力和 `instructions`）。

## 三步才能跑起来

**① 授予工具** —— 控制台「工具」页，`qdash_neo_bili` 点「授予」

**② 允许引导** —— 同页「插件引导」栏，点「允许」

没有引导它根本想不起来去逛。

**③ 扫码登录**（可选，但强烈建议）—— 「B 站」选项卡 → 「生成二维码」→ 手机 B 站扫

| 没登录 | 登录后 |
|---|---|
| 只能看热门榜和分区榜 | 还能按关键词搜 |

**为什么搜索必须登录**：B 站的搜索接口对这个 IP 一律 412，
加了 wbi 签名也一样；带 `SESSDATA` 才放行（实测过）。

## 它能做什么

| 工具 | 作用 | 要登录 |
|---|---|---|
| `bili_hot` | 热门榜 / 分区排行榜 | ❌ |
| `bili_find` | 按关键词搜视频 | ✅ |

分区名直接传中文：`游戏` `科技` `动画` `搞笑` `影视` `音乐` `知识` `美食` `动物`…

模型拿到列表里的 `title` / `cover` / `url`，直接喂给内核的 `qq_send_card`。

## 发出去长什么样

```
[卡片] 哔哩哔哩
       旗舰手机芯片大横评：苹果高通发哥玄戒谁最强？
       （封面图）

这个横评把 A20 Pro 和骁龙 8 Elite 的能效曲线放在一张图里比，
评论区在吵测试条件不公平
```

**卡片 + 一条文字**。卡片里只有标题和封面，正文读不到，所以评价得单独发 ——
这条写进了工具 description 和引导，否则模型会把评价塞进 `card` 的 `desc` 里，
结果群里只看到一张没有态度的卡片。

## 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉就不排期 |
| `minMinutes` / `maxMinutes` | `180` / `480` | 随机间隔，**不是固定 cron** |
| `chatKeys` | `[]` | 发到哪些群；留空则用内核 `policy.groupWhitelist` |
| `limit` | `6` | 每次给几条候选 |

**为什么用随机间隔**：固定 4 小时一次，两天之后群里就会觉得「它怎么老在这个点发」。

## 已知限制

**依赖 SnowLuma 的 `get_mini_app_ark` 才能发真卡片。**

换 NapCat / Lagrange / 自建实现时，内核的 `card.share` 会**自动降级成纯文本**
（标题 + 链接），不会报错、不会静默失败。降级后群里看到的是一条带链接的消息。

**搜索靠 cookie，会过期。** 过期后 `bili_find` 会明确报「B 站没登录，搜不了」，
而不是返回空列表 —— 空列表会被模型理解成「今天没什么好分享的」，然后静默不发。

**没有“看完再评价”**。模型只拿到标题、UP 主、播放量，没看内容。
所以评价多半是基于标题和常识的猜测，别指望它真的评到点子上。
想让它看得更准，可以再加一步拿字幕（B 站有字幕接口，但要另外爬）。

## 不依赖别的插件

社区里的 `dsh-bili-scroll` 也提供 B 站工具（`bili_search` 等），
本插件**不用它** —— 那等于把一个功能的稳定性挂在别人插件的更新节奏上。

所以工具名特意避开了：`bili_hot` / `bili_find`，不是 `bili_search`。
